# Базовый мультиагент для учеников

Это самый простой учебный пример мультиагента.

Идея:

```text
Пользователь пишет один запрос.
Главный агент-диспетчер решает, кому отдать задачу.
Субагенты отвечают каждый со своей роли.
Финальный редактор собирает общий ответ.
```

## Как запустить

Перейдите в папку проекта:

```bash
cd multiagent-basic
```

Запуск без API-ключей:

```bash
npm run demo
```

Или свой запрос:

```bash
npm start "Хочу сделать Telegram-бота для записи клиентов"
```

Если запрос не передать, программа спросит его в терминале.

## Как подключить реальный API

Скопируйте файл настроек:

```bash
cp .env.example .env
```

Откройте `.env` и выберите провайдера:

```env
AI_PROVIDER=openai
OPENAI_API_KEY=ваш_ключ
OPENAI_MODEL=gpt-4o-mini
```

или:

```env
AI_PROVIDER=anthropic
ANTHROPIC_API_KEY=ваш_ключ
ANTHROPIC_MODEL=claude-3-5-haiku-latest
```

Потом:

```bash
npm start "Разработай план запуска лендинга для психолога"
```

## Контентный мультиагент

В проекте есть второй сценарий: контентная цепочка.

Она работает так:

```text
1. Агент-исследователь собирает информацию в интернете.
2. Агент-копирайтер пишет Telegram-пост.
3. Агент-дизайнер генерирует картинку.
4. Telegram-агент публикует пост в канал или чат.
```

## Важный момент про подписку и API

Если вы работаете с Claude/Claude Code по подписке, то AI-части можно делать прямо через Claude Code в VS Code:

```text
Claude Code ищет информацию,
Claude Code пишет пост,
Claude Code генерирует картинку,
Claude Code помогает подготовить публикацию.
```

Это называется `Claude-assisted mode`.

Но локальная программа `node src/content-pipeline.js` не может сама "использовать подписку" как API. Если нужно, чтобы скрипт работал полностью автономно без участия человека, тогда нужен отдельный API-ключ.

Для учеников самый простой учебный путь:

```text
1. Сначала понять схему через demo.
2. Потом запускать контентного мультиагента через Claude Code в VS Code.
3. Потом, если нужна полная автоматизация, подключать API и Telegram-бота.
```

### Демо без ключей

```bash
npm run content:demo
```

Или со своей темой:

```bash
npm run content -- "Как малому бизнесу внедрить ИИ без хаоса"
```

В demo-режиме:

- интернет не используется;
- API-ключи не нужны;
- картинка создается как учебный SVG-файл;
- публикация в Telegram не выполняется.

### Автопостинг по расписанию

Автопостинг работает как отдельный локальный процесс. Он не зависит от открытого
чата с Claude Code: планировщик сам запускает контентный пайплайн в нужное время.

Важно: для полностью автономного режима нужен API-ключ, потому что локальный
Node.js-скрипт не может использовать подписку Claude/Claude Code как API.

Минимальные настройки в `.env`:

```env
CONTENT_PROVIDER=openai
OPENAI_API_KEY=ваш_ключ
USE_WEB_SEARCH=true
GENERATE_REAL_IMAGE=true
POST_TO_TELEGRAM=true
TELEGRAM_BOT_TOKEN=токен_бота
TELEGRAM_CHAT_ID=chat_id_канала
AUTOPOST_TIMES=09:00,14:00,19:00
```

Темы берутся из `content-topics.json`. Планировщик публикует следующую тему и
запоминает уже использованные темы в `outputs/autopost-state.json`.

Опубликовать одну следующую тему и выйти:

```bash
npm run content:auto
```

Запустить постоянный планировщик:

```bash
npm run content:scheduler
```

Запустить планировщик и сразу сделать первый пост:

```bash
npm run content:scheduler:now
```

Пока процесс запущен и компьютер/сервер имеет интернет, он будет публиковать по
расписанию. Если терминал закрыть или компьютер выключить, локальный
планировщик остановится.

Результаты сохраняются в:

```text
outputs/content-runs/
```

### Реальный режим

В `.env`:

```env
CONTENT_PROVIDER=openai
OPENAI_API_KEY=ваш_ключ
OPENAI_TEXT_MODEL=gpt-4.1-mini
USE_WEB_SEARCH=true
```

Если нужна реальная генерация картинки:

```env
GENERATE_REAL_IMAGE=true
OPENAI_IMAGE_MODEL=gpt-5.5
```

Если нужна публикация в Telegram:

```env
POST_TO_TELEGRAM=true
TELEGRAM_BOT_TOKEN=токен_бота
TELEGRAM_CHAT_ID=@username_канала_или_id_чата
```

Запуск:

```bash
npm run content -- "5 ошибок предпринимателей при внедрении ИИ"
```

Важно: бот должен быть добавлен в канал/чат и иметь право публиковать сообщения.

## Какие агенты есть

### 1. Диспетчер

Решает, какие субагенты нужны для задачи.

### 2. Аналитик

Разбирает смысл задачи, цель, аудиторию, риски и вопросы.

### 3. Технический агент

Предлагает инструменты, архитектуру и пошаговую реализацию.

### 4. Маркетолог

Думает про оффер, упаковку, монетизацию и привлечение клиентов.

### 5. Редактор

Собирает ответы субагентов в один понятный финальный ответ.

## Главное объяснение для учеников

Агент - это не магия.

В этом примере агент - это:

```text
роль + инструкция + входные данные + ответ
```

Мультиагент - это когда один запрос разбивается на несколько ролей:

```text
аналитик думает о смысле,
технарь думает о реализации,
маркетолог думает о продаже,
редактор собирает всё вместе.
```
